# 2.4-数据加载与批次

数据集定义“怎样取得一个样本”，数据加载器负责“按什么顺序、一次取多少样本”。在 PyTorch 中，这两项职责通常分别由 `Dataset` 和 `DataLoader` 承担。

## 2.4.1-Dataset与DataLoader

对于可以按索引访问的数据集，`Dataset` 通常提供 `__len__` 和 `__getitem__`：前者返回样本总数，后者根据索引返回一个样本。MNIST 的一个样本由图片与类别标签组成，取样时会对图片应用指定的变换。

`DataLoader` 按设定的顺序读取多个样本，并把它们组合成批次。在本例中，它将 $B$ 个形状为 `[1,28,28]` 的图像张量沿新轴堆叠，形成 `[B,1,28,28]`，同时把 $B$ 个整数标签组合为形状 `[B]` 的标签张量。

| 设置 | 本例取值 | 含义 |
| --- | --- | --- |
| `batch_size` | 64 | 每个完整批次包含 64 个样本 |
| 训练集的 `shuffle` | `True` | 每轮重新打乱样本顺序，避免固定排列持续影响训练 |
| 验证集和测试集的 `shuffle` | `False` | 按固定次序读取，便于核对预测结果 |
| `drop_last` | `False` | 保留最后一个不足 64 个样本的批次 |
| `num_workers` | 0 | 由当前进程加载数据，便于在 Windows Notebook 中运行 |

打乱顺序不改变图片与其标签的对应关系，也不把训练集和验证集合并。数据划分决定“样本属于哪个集合”，`shuffle` 决定“集合内部以什么顺序取样”。

`num_workers` 表示加载数据的工作进程数，不是模型训练的线程数，也不决定模型使用 CPU 还是 GPU。

## 2.4.2-Batch、Step与Epoch

| 概念 | 含义 | 在本例中的关系 |
| --- | --- | --- |
| batch | 一次送入模型的一组样本 | 通常为 64 张图片 |
| iteration | 训练循环的一次迭代 | 处理一个训练 batch |
| step | 通常指一次优化器更新 | 每个训练 batch 更新一次参数 |
| epoch | 完整遍历一次训练集 | 包含多个 batch 和多次参数更新 |

本例每轮训练处理 55,000 个样本，保留末尾不足一个批次的数据，因此：

$$
\text{每轮批次数}
=\left\lceil\frac{55000}{64}\right\rceil
=860.
$$

前 859 批共包含 $859\times64=54,976$ 个样本，最后一批有 24 个样本。训练 3 个 epoch 时，共执行 $860\times3=2,580$ 次参数更新；每个训练样本会被访问 3 次。

批次变大会减少同一 epoch 中的更新次数，还会改变单次计算所需的内存和梯度估计的波动。因此比较不同 batch size 时，应同时记录训练轮次、更新次数与耗时。如果使用梯度累积，处理多个 batch 后才执行一次 `step()`，iteration 与 step 就不再一一对应。
