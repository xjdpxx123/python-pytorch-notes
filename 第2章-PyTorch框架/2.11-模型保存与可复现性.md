# 2.11-模型保存与可复现性

需要保存哪些内容，取决于接下来只进行预测，还是要从中断处继续训练。

## 2.11.1-模型状态与推理恢复

模型的 `state_dict` 是名称到状态张量的映射，包含可学习参数，以及被登记为持久状态的缓冲区。例如 Linear 的权重和偏置属于参数，BatchNorm 的运行均值和方差属于缓冲区。本例的 MLP 主要需要保存各线性层的权重与偏置。

`state_dict` 不包含模型类的完整定义。恢复预测通常需要：

1. 建立结构与保存时一致的模型。
2. 加载模型状态，并根据目标环境选择设备。
3. 调用 `model.eval()`，在关闭梯度记录的范围内预测。
4. 使用与训练时一致的图像预处理和类别编号解释结果。

模型结构不一致时，状态中的名称或张量形状可能无法匹配；预处理不一致时，即使权重成功加载，预测结果也可能明显变化。因此，权重文件应与网络配置和预处理规则一起保存。

选择“验证损失最低的模型”时，要保存该轮的独立状态。仅把 `model.state_dict()` 赋给一个变量，并不自动复制其内部张量；继续训练可能使变量引用的状态随之变化。可以立即写入文件，或对状态进行深复制后再保留。

## 2.11.2-推理与断点续训的区别

| 保存内容 | 恢复推理 | 完整续训时的作用 |
| --- | --- | --- |
| 模型状态 | 必需 | 恢复权重与持久缓冲区 |
| 网络结构与预处理配置 | 必需 | 保持计算流程一致 |
| 优化器状态 | 通常不需要 | 恢复动量、Adam 的历史矩估计等 |
| 已完成轮次与训练进度 | 通常不需要 | 确定从哪里继续 |
| 学习率调度器状态 | 通常不需要 | 若使用调度器，恢复其进度 |
| 随机数与数据加载状态 | 通常不需要 | 更准确地延续随机顺序与随机操作 |
| 最佳验证指标与训练配置 | 便于说明结果 | 保持模型选择规则一致 |

只恢复权重再重新创建 Adam，等于使用已有权重启动一次新的优化过程；它没有恢复原来的历史状态，因此不等同于完整断点续训。若要求精确续接到某个 batch，还需要记录该轮已经读取到哪里，不能只记录 epoch 编号。

## 2.11.3-控制随机性与记录环境

模型初始化、数据划分、样本打乱和部分训练操作都会引入随机性。固定 Python、NumPy 与 PyTorch 的随机种子，可以减少重复运行时的差异。为数据划分和训练打乱分别设置随机生成器，还能避免某一环节多消耗一次随机数就改变其他环节的顺序。

可复现性还依赖计算设备、库版本、算子实现与数据处理方式。固定种子不保证不同平台或不同版本得到逐位相同的结果；某些算子还需要额外的确定性设置。

为了让结果能够被核对，实验记录至少应包括数据划分、随机种子、网络结构、优化器、学习率、batch size、训练轮次、预处理方式、设备与软件版本。比较两个配置时，先固定这些条件，再改变待研究的因素，才能更清楚地解释性能差异。
